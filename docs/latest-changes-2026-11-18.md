# Alignment audit: latest Cloudflare CLI and Artifacts changes (18 Nov 2026)

Triggered by two posts: the Cloudflare changelog for local Artifacts development (16 Nov 2026) and the release-candidate
announcement for the Cloudflare CLI `cf` 1.0 (17 Nov 2026, posted by @MattieTK).

## Method

- Read the official sources: the `cf` 1.0 release-candidate changelog, the Artifacts changelog, the Artifacts pricing and
  limits pages, the Artifacts REST quick start, and the wrangler 4.165.0 release notes (workers-sdk).
- Checked npm for the latest version of every pinned tool. Pi 1.5.2 and `cf` 1.0.0-rc.1 are still the latest.
  Wrangler is 4.165.0 (we were on 4.164.0). `@platformatic/vfs` 0.5.0 and `@cloudflare/computer` 0.11.3 are current.
  TypeScript 7.0.2 is out; see Deferred.
- Searched every tracked file for `cf`, `wrangler`, Artifacts, Cloudflare account and billing terms. The Cloudflare
  AI Gateway and Workers AI keys in `dpi-backend`, `dpi-sdk`, `dpi-tui`, `dpi-playground` and the proactive demo are
  unchanged APIs, so they need no change. The `exe.dev` skill is unrelated.

## Checked, no change needed

- `apps/pi-object/scripts/ensure-spend-limits.mjs`: runs `cf billing spend-policies` and parses **stdout**. In `cf`
  1.0 RC, status goes to stderr, so the JSON still parses (verified, `nothing to change`). It runs from
  `apps/pi-object`, where `.env` supplies the account. The update and create calls are not destructive, so the new
  "destructive commands need `--force` without a terminal" rule does not apply.
- `apps/pi-object/e2e/e2e.mts`: uses the Artifacts REST paths from the quick start (namespace create, repo create,
  repo delete returning 202, namespace delete returning 204). These are unchanged.
- `apps/pi-object/wrangler.jsonc`: `nodejs_compat`, `workers_dev`, `limits`, the DO migration and `worker_loaders` are
  unchanged in 4.165.0. The `.dev.vars.example` file is ASCII, so the new UTF-8 check does not affect it.
- `apps/pi-object/src/cost/cloudflare-rate-card.ts`: uses the Billing REST endpoints; `cf schema` still lists them.
- `.dev.vars.example`, `.env.example`: no CLI behaviour involved.
- `cf` is installed at 1.0.0-rc.1 (the release candidate). Node 26 meets its support statement (latest LTS and latest
  active).

## Deferred (decided, with reasons)

- **Compatibility date** (`wrangler.jsonc`, `2026-05-26`). The Artifacts docs suggest today's date for new features, but
  a date change alters runtime behaviour. Left as is until the Worker is tested on a newer date.
- **Moving the Worker from wrangler config to `cloudflare.config.ts` and `cf deploy`.** `cf` 1.0 supports existing
  wrangler projects (`cf migrate`), and the config format is now stable. The Worker is deployed and tested on
  wrangler, so the move waits for its own change.
- **TypeScript 7.0.2.** It's a major version, and the project pins `^6.0.3`. Adopting it needs its own test run.
- **Offline Artifacts e2e** using `wrangler dev` (local simulator by default). Worth building as a third leg; it is not
  needed for the remote-repo proof.
- **Artifacts jurisdiction.** Test namespaces are unpinned. Pin to US or EU for any real data.
- **Artifacts repo-count billing.** Not started on 19 Nov. Cloudflare will announce it. Track on the pricing page.

## Permissions and accounts (learned during the audit)

- The deploy token needs `Artifacts Read` and `Artifacts Write`. The docs call the second one "Edit".
- `cf` 1.0 RC no longer remembers the account. `.env` sets `CLOUDFLARE_ACCOUNT_ID`; without it, `cf` uses the sole account
  on the profile, and prompts when there are several.
